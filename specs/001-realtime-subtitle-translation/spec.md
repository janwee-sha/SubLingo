# Feature Specification: SubLingo 实时字幕翻译 MVP

**Feature Branch**: `未创建（项目未配置 before_specify 分支钩子）`

**Created**: 2026-08-09

**Status**: Draft

**Input**: User description: "SubLingo 是一款 IINA 实时字幕插件：读取当前 SRT / ASS 字幕，按观看位置提前批量调用机器翻译、OpenAI-compatible API 或 Ollama API，缓存译文并通过 IINA 第二字幕显示；仅翻译非母语字幕，且不预先翻译整部视频，以控制 AI Token 消耗。完成插件 MVP。"

## Clarifications

### Session 2026-08-09

- Q: 插件保存翻译服务凭据时，必须采用哪种存储方式？ → A: 加密后保存到插件本地存储
- Q: 本地译文缓存应保留到何时并以什么规则删除？ → A: 视频关闭时立即删除

### Session 2026-08-10

- Q: 翻译请求遇到超时、断网或限流等临时错误时，插件应如何重试？ → A: 最多自动重试 3 次，逐次延长等待时间并遵守服务重试时间
- Q: 首次向远程翻译服务发送字幕前，插件是否必须取得用户的明确确认？ → A: 用户选择服务即视为同意，无需额外确认
- Q: 当 IINA 同时播放多个视频窗口时，MVP 应支持多少个实时翻译会话？ → A: 所有窗口均可独立并发翻译

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 观看实时双语字幕 (Priority: P1)

作为使用 IINA 观看外语视频的用户，我希望插件读取当前选中的文本字幕，并在播放进度附近提前翻译接下来会出现的若干条字幕，使原字幕保持可见的同时，母语译文作为第二字幕与画面同步显示。

**Why this priority**: 这是产品的核心价值；只要一条受支持的字幕轨和一个可用翻译服务即可独立交付完整的观看体验。

**Independent Test**: 准备一段带有非母语 SRT 或 ASS 字幕的短视频，配置任一可用翻译服务并连续播放；验证原字幕未被替换，第二字幕按相同时间轴显示母语译文，且播放不会因翻译而暂停。

**Acceptance Scenarios**:

1. **Given** 用户已设置母语、当前字幕语言与母语不同且翻译服务可用，**When** 用户开始或继续播放，**Then** 插件翻译当前播放位置附近的字幕，并在对应时间以第二字幕显示译文。
2. **Given** 当前字幕为 SRT 或 ASS 且含多行字幕、重叠时间段或 ASS 控制标记，**When** 译文显示，**Then** 每条译文保持原条目的起止时间和顺序，换行语义可读，控制标记不会作为普通文本显示。
3. **Given** 翻译尚未完成，**When** 某条原字幕到达显示时间，**Then** 视频和原字幕继续正常播放，译文轨不显示错误、占位符或过期译文。
4. **Given** 用户暂停后继续播放，**When** 后续字幕进入临近播放范围，**Then** 插件继续补充译文而不要求重新加载视频或字幕。
5. **Given** 实时翻译正在运行且仍有待处理批次，**When** 用户禁用插件翻译，**Then** 插件不再创建或接受该会话的翻译结果，移除插件管理的第二字幕，并保持视频与原字幕播放。
6. **Given** 多个 IINA 视频窗口均已启用实时翻译，**When** 这些视频同时播放、跳转或分别发生服务错误，**Then** 每个窗口独立维护播放位置、请求、缓存、状态和第二字幕轨，任一窗口的结果或故障不得影响其他窗口。

### User Story 2 - 只翻译所需内容并复用译文 (Priority: P2)

作为关注费用和隐私的用户，我希望插件只在字幕并非我的母语时，围绕实际观看位置按批次提交有限的字幕内容，并在当前视频会话内复用已完成的译文，避免翻译整部视频或在同一会话内重复消耗 Token。

**Why this priority**: 有限预取、语言门控和缓存共同满足用户明确提出的成本约束，也是用户愿意持续启用 AI 翻译的前提。

**Independent Test**: 使用可记录调用内容和次数的测试翻译服务，分别验证连续播放、向前跳转、向后跳转、同一会话内重放、关闭后重新打开视频和母语字幕；观察提交范围、会话内缓存复用及视频关闭后的缓存删除行为。

**Acceptance Scenarios**:

1. **Given** 一部至少 60 分钟的视频刚开始播放且字幕为非母语，**When** 用户只观看前 10 分钟，**Then** 插件仅提交已观看位置及有限前瞻范围内的字幕，不提交其余整部视频的字幕。
2. **Given** 当前字幕语言与用户母语相同，**When** 用户播放、暂停或拖动进度，**Then** 插件不调用任何翻译服务，并向用户表明无需翻译。
3. **Given** 某段字幕已在当前视频会话中成功翻译且相关输入没有变化，**When** 用户向后跳转并重播该段字幕，**Then** 插件直接复用缓存译文，不重复提交该段字幕。
4. **Given** 用户跳转到尚未翻译的远处，**When** 新位置稳定下来，**Then** 插件停止为旧位置补充不再需要的字幕，并从新位置附近开始新的有限批次。
5. **Given** 字幕语言无法可靠确定，**When** 播放开始，**Then** 插件不发送字幕内容，并提示用户先确认源语言。
6. **Given** 用户选择了一个可记录请求内容的翻译服务，**When** 插件提交临近字幕批次，**Then** 请求只包含这些字幕的文本、语言方向和翻译所需的最少上下文，不包含视频文件内容或无关用户数据。
7. **Given** 当前视频会话中存在已缓存译文，**When** 用户关闭视频，**Then** 插件立即删除该视频会话的全部译文缓存，之后重新打开同一视频时不复用先前会话的译文。

### User Story 3 - 配置并切换翻译服务 (Priority: P3)

作为用户，我希望在一款内置机器翻译服务、任意 OpenAI-compatible 服务和 Ollama 服务之间选择，填写每类服务所需的连接信息并验证配置，从而按成本、质量或本地隐私需求选择译文来源。

**Why this priority**: 多类服务是 MVP 的明确范围，但在核心观看流程已由任一服务跑通后，可作为独立能力逐项验收。

**Independent Test**: 分别保存三类服务配置、执行连接检查，再用同一小段非母语字幕完成翻译；验证成功配置可被选择，错误配置有明确反馈，切换服务后不会误用其他服务的缓存结果。

**Acceptance Scenarios**:

1. **Given** 用户选择内置机器翻译服务并提供其必需配置，**When** 连接检查通过并开始播放，**Then** 该服务可产生同步的第二字幕译文。
2. **Given** 用户提供 OpenAI-compatible 服务地址、模型标识和所需凭据，**When** 连接检查通过，**Then** 用户可将其设为当前翻译服务并完成批量字幕翻译。
3. **Given** 用户提供 Ollama 服务地址和模型标识，**When** 连接检查通过，**Then** 用户可将其设为当前翻译服务并完成批量字幕翻译。
4. **Given** 配置缺失、服务不可达、凭据无效、模型不可用或服务限流，**When** 用户检查连接或播放视频，**Then** 插件给出可理解且可操作的错误状态，保留用户设置，并且不影响视频与原字幕播放。
5. **Given** 用户切换服务、模型、源语言或母语，**When** 翻译继续，**Then** 新产生的译文与旧配置结果相互隔离，第二字幕不会混用不匹配的缓存。
6. **Given** 用户已保存包含机密凭据的服务配置，**When** 用户查看设置、普通状态消息或可复制诊断信息，**Then** 完整凭据不会以明文显示，字幕也只会发送到当前明确选择的服务。
7. **Given** 用户已查看某个远程服务的类别和地址并将其选为当前翻译来源，**When** 插件提交字幕批次，**Then** 该主动选择视为用户授权发送，无需在首次发送或每个视频、批次前再次确认。

### Edge Cases

- 当前视频没有字幕、没有选中字幕，或选中的字幕不是可读取的 SRT/ASS 文本字幕时，插件不发起翻译，并说明当前字幕不受支持或不可用。
- 字幕文件为空、损坏、编码异常，或某些条目缺少有效时间轴时，插件忽略无法安全处理的条目并报告问题，不阻断视频播放。
- 用户快速、连续拖动进度时，插件等待播放位置稳定后只服务最终位置，迟到的旧请求结果不得覆盖新位置的第二字幕。
- 翻译服务部分返回、返回条数与请求不一致、返回空文本或不可解析内容时，插件只缓存可明确对应的有效译文；缺失条目保持未翻译并允许后续重试。
- 网络中断、服务超时、限流或本地 Ollama 停止运行时，插件保持原字幕和视频可用，以非阻塞状态提示失败，并按限定重试规则继续仍属当前临近范围的未完成字幕。
- 用户在播放中更换字幕轨、字幕文件内容发生变化，或加载另一部同名视频时，插件重新判断字幕身份和语言，不复用无法确认匹配的缓存。
- 字幕语言与母语属于同一语言的不同地区变体时，默认视为同一语言而不翻译；用户可通过明确选择不同目标语言来覆盖该判断。
- 单条字幕极长、包含纯音乐符号、说话人标记、网址或大量重复文本时，插件保持时间轴可用，只将需要翻译的人类可读内容纳入请求，无法翻译的内容原样保留或不生成第二字幕。
- 多条字幕共享相同文本时，插件可复用相同语言和翻译设置下的有效译文，但仍按各自时间轴显示。
- 用户关闭插件、禁用翻译或结束播放时，待处理结果不再写入当前第二字幕轨，且不会影响下一次播放会话。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 插件 MUST 在 IINA 中识别并读取当前选中的、可访问的 SRT 或 ASS 文本字幕及其条目文本、顺序和起止时间。
- **FR-002**: 用户 MUST 能设置母语，并能确认或选择当前字幕的源语言；当可靠的字幕语言信息可用时，插件 MAY 自动填写源语言供用户使用。
- **FR-003**: 插件 MUST 在提交任何字幕前比较源语言与母语；两者相同时不得调用翻译服务。
- **FR-004**: 当源语言无法可靠确定且用户未明确选择时，插件 MUST 阻止字幕外发并提示用户确认源语言。
- **FR-005**: 插件 MUST 以当前播放位置为中心安排翻译，只处理当前条目和后续有限范围，不得在用户开始观看时预先翻译整部视频。
- **FR-006**: 单次待翻译范围 MUST 不超过当前播放位置之后 120 秒或 40 条字幕（以先达到者为准），并且 MUST 将多条临近字幕组成批次提交，而不是默认逐条调用。
- **FR-007**: 连续播放时，插件 MUST 在未处理的前瞻余量低于 30 秒或 10 条字幕（以先达到者为准）后补充下一有限批次，以维持实时观看所需的译文供给。
- **FR-008**: 播放位置发生跳转时，插件 MUST 优先服务新位置；不再属于新位置临近范围的未开始工作 MUST 停止，已返回的过期结果不得写入当前第二字幕轨。
- **FR-009**: 插件 MUST 将译文作为与原字幕并存的 IINA 第二字幕显示，不得替换、改写或隐藏用户的原字幕轨。
- **FR-010**: 每条有效译文 MUST 保持对应原字幕条目的起止时间与显示顺序；多行语义必须保持可读，ASS 控制标记不得作为普通文字出现在译文中。
- **FR-011**: 翻译未及时完成或翻译失败时，插件 MUST 允许视频和原字幕无中断继续播放，并且不得在第二字幕位置显示错误映射、过期内容或技术错误文本。
- **FR-012**: 插件 MUST 在当前视频会话内缓存每条成功且可明确映射的译文，并在同一字幕内容、相同源语言、母语和翻译设置下的跳转及重播时复用缓存。
- **FR-013**: 缓存 MUST 隔离不同视频、字幕版本、源语言、母语、服务、模型或影响翻译语义的设置；任一相关输入变化后不得复用不匹配结果。
- **FR-014**: 插件 MUST 为 MVP 提供且仅承诺以下三类翻译来源：一款指定的内置机器翻译服务、OpenAI-compatible 服务和 Ollama 服务。
- **FR-015**: 用户 MUST 能选择当前翻译来源，保存其必需的服务地址、模型标识和凭据（仅在该来源需要时），并在正式观看前执行连接检查。
- **FR-016**: 插件 MUST 对缺失配置、连接失败、无效凭据、不可用模型、超时、限流和无效返回提供可理解且可操作的状态，不得要求用户通过调试日志才能识别常见问题。
- **FR-017**: 需要保密的凭据 MUST 在写入插件本地存储前加密，且不得以可直接读取的明文形式保存在磁盘上；凭据在界面中 MUST 默认遮蔽，不能出现在普通状态消息或可直接复制的诊断内容中；字幕内容只能发送给用户当前明确选择的服务。
- **FR-018**: 提交给翻译服务的内容 MUST 限于生成当前临近译文所需的字幕文本、语言方向和最少必要上下文，不得附带不相关的视频文件内容或用户数据。
- **FR-019**: 插件 MUST 将服务返回中的每条译文与原批次条目做明确对应；无法对应、缺失、空白或无效的结果不得缓存为成功译文。
- **FR-020**: 对超时、网络中断、限流或服务明确标识为临时性的失败，插件 MUST 为每个未成功批次最多自动重试 3 次，等待时间 MUST 逐次延长，并在服务提供重试时间时遵守该时间；已经成功缓存的相同输入不得重试，视频关闭、翻译禁用或批次因跳转或配置变化而过期后 MUST 取消剩余重试。
- **FR-021**: 用户 MUST 能查看插件当前处于无需翻译、等待配置、准备译文、正常运行、部分失败或服务不可用中的哪一种状态。
- **FR-022**: 用户 MUST 能在播放期间启用或禁用实时翻译；禁用后不再创建新请求、不再接受过期待处理结果，并移除由插件管理的第二字幕显示。
- **FR-023**: 用户关闭视频时，插件 MUST 立即删除该视频会话的全部译文缓存；后续重新打开同一视频时不得复用上一会话的译文。
- **FR-024**: 插件 MUST 在用户选择远程翻译来源前清楚显示其服务类别和目标地址；用户主动将其选为当前翻译来源即视为授权向该地址发送符合 FR-018 的字幕内容，插件不得要求首次发送、每个视频或每个批次再次确认。服务地址变化后，用户 MUST 重新选择该配置后方可发送。
- **FR-025**: 插件 MUST 支持多个 IINA 视频窗口同时运行实时翻译；每个窗口 MUST 使用独立的播放上下文、请求队列、重试状态、译文缓存、运行状态和第二字幕轨，一个窗口中的播放控制、配置变化、禁用、关闭、失败或迟到结果不得改变或污染其他窗口的翻译会话。

### Key Entities

- **用户语言偏好**: 用户的母语、明确选择的字幕源语言，以及是否允许使用可靠语言信息自动填写源语言。
- **字幕源**: 当前视频所选的 SRT/ASS 字幕身份、内容版本、语言及有序字幕条目集合。
- **字幕条目**: 一段带有唯一对应关系、文本、起始时间、结束时间和顺序的原字幕内容。
- **播放上下文**: 单个 IINA 视频窗口的视频身份、播放位置、播放/暂停状态、当前字幕源，以及决定临近翻译范围的独立会话状态；多个窗口各自拥有一个播放上下文。
- **翻译服务配置**: 服务类别、用户可识别的配置名称、服务地址、模型标识、所需凭据、连接状态及当前选用状态。
- **翻译批次**: 围绕某一播放位置选出的有限字幕条目、语言方向、服务设置、请求状态和条目对应关系。
- **译文缓存项**: 当前视频会话内的原字幕内容及其身份、语言方向、翻译设置、译文、成功状态和用于判断是否可安全复用的信息；其生命周期不超过所属视频会话。
- **第二字幕轨**: 由有效缓存译文按原时间轴组成、与原字幕同时显示且可随插件状态更新的母语字幕集合。

### Scope Boundaries

**In Scope**:

- IINA 内当前选中 SRT/ASS 文本字幕的读取、语言门控、有限前瞻批量翻译、缓存和第二字幕显示。
- 一款机器翻译服务、OpenAI-compatible 服务和 Ollama 服务的配置、连接检查与翻译使用。
- 播放、暂停、跳转、切换字幕、切换服务以及常见失败状态下的连续观看体验。

**Out of Scope for MVP**:

- 音频转写、语音识别、字幕生成或时间轴自动校正。
- 图形字幕（例如 PGS）、无法读取的内嵌字幕格式，以及 SRT/ASS 之外格式的正式兼容承诺。
- 整部视频的一键预翻译、离线批量导出、人工编辑译文或把译文写回原字幕文件。
- 在同一视频窗口内同时翻译多个字幕轨或向多个目标语言输出。
- 除指定的一款机器翻译服务、OpenAI-compatible 服务和 Ollama 服务以外的其他服务适配。
- 跨设备同步设置或译文缓存、多人共享缓存，以及翻译质量的人工审核工作流。

### Dependencies

- 依赖 IINA 提供插件运行能力、当前播放状态、可读取文本字幕和第二字幕显示能力。
- 依赖用户选择的翻译服务处于可用状态，并由用户自行满足相应的账户、网络、本地模型、费用和使用条款要求。
- 规划阶段需要从可用性、地区覆盖、凭据要求和维护成本中选定 MVP 唯一内置机器翻译服务。
- 翻译质量、内容政策、响应速度和可用性受所选外部或本地模型服务影响；插件负责请求范围、映射和观看连续性，不保证语义翻译达到专业人工翻译水平。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在翻译服务于 3 秒内返回有效批次的受控测试中，用户开始播放非母语字幕视频后，首条可用第二字幕译文在 5 秒内准备完成。
- **SC-002**: 在连续播放且翻译服务满足上述响应条件时，首批完成后至少 95% 的后续字幕在其开始显示前已有正确对应的母语译文，且原视频播放因插件造成的暂停次数为 0。
- **SC-003**: 用户只观看一部至少 60 分钟视频的前 10 分钟时，发送给翻译服务的字幕不得超出实际到达位置之后 120 秒或 40 条字幕的边界，也不得包含视频剩余部分的字幕。
- **SC-004**: 对源语言与母语相同的字幕，在包含播放、暂停和 10 次随机跳转的测试会话中，翻译服务调用次数为 0。
- **SC-005**: 对已完整翻译且输入未变化的 5 分钟片段，向后跳转并重播该片段时，至少 99% 的字幕条目直接使用缓存，已成功条目的重复翻译调用次数为 0。
- **SC-006**: 对每一种 MVP 翻译来源，用户可在 3 分钟内从空白设置完成必需配置、连接检查并选为当前服务；错误配置均能在不查看调试日志的情况下识别下一步处理动作。
- **SC-007**: 在 SRT 与 ASS 验收样本中，100% 的成功译文保持与原条目相同的起止时间和顺序，且不存在来自其他条目、服务、语言或旧播放位置的错配译文。
- **SC-008**: 在包含服务超时、限流、断网、无效返回和本地服务退出的故障测试中，100% 的场景保持视频与原字幕可继续播放，并向用户显示明确的非阻塞状态；每个临时失败批次的自动重试不超过 3 次，等待时间逐次延长，并遵守服务提供的重试时间。
- **SC-009**: 在 10 名目标用户的可用性测试中，至少 9 名无需开发者协助即可完成“设置母语—选择服务—播放外语字幕—看到第二字幕译文”的主任务。
- **SC-010**: 在至少 2 个 IINA 视频窗口同时翻译并分别执行播放、跳转、服务切换、禁用和关闭操作的测试中，100% 的译文、缓存、状态和第二字幕更新仅作用于所属窗口，且任一窗口的服务失败不阻断其他窗口的视频、原字幕或翻译流程。

## Assumptions

- MVP 面向单一 IINA 桌面用户和单机观看场景，用户已安装支持插件与第二字幕显示的兼容 IINA 版本；同一用户可在多个 IINA 视频窗口中并发使用实时翻译。
- “母语”由用户明确设置；语言地区变体默认归为同一基础语言，除非用户明确选择不同目标语言。
- 只有在可靠字幕语言信息存在或用户明确选择源语言后才允许外发字幕；MVP 不要求通过远程服务识别语言。
- 有限前瞻的默认上限采用 120 秒或 40 条字幕，补充阈值采用剩余 30 秒或 10 条字幕；这些值服务于 MVP 的成本与实时性平衡，未来可基于验证结果开放调整。
- 成功译文仅在当前视频会话内缓存；用户关闭视频时立即删除该会话的全部译文缓存，重新打开同一视频时重新建立缓存。
- 每个视频窗口的翻译会话仅有一个翻译来源和一个目标语言处于活动状态；不同窗口可并发运行，服务切换后新结果使用该窗口内独立的缓存身份。
- “OpenAI-compatible”表示用户选择的服务能够接受兼容的模型、凭据和批量文本翻译配置；不同厂商的非标准扩展不在 MVP 保证范围内。
- Ollama 默认代表用户自行运行和管理的本地服务；插件不负责下载模型、启动服务或管理模型存储。
- 一款具体机器翻译服务的选择留到规划阶段，不扩大为多款机器翻译服务；选择不改变本规格定义的用户行为与验收结果。
- 外部服务可能接收用户选择翻译的字幕文本；插件清楚显示当前服务类别，用户对该服务的隐私条款、费用和内容政策负责。
- 用户主动选择一个已显示类别和目标地址的远程服务，即授权插件向该地址发送必要字幕内容；首次发送及后续视频或批次无需额外确认。
