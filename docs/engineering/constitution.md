# SubLingo 项目宪法

## 核心原则

### I. 验证与产品安全

变更 MUST 按风险比例接受验证，并 MUST 保持 SubLingo 的核心安全属性：原始播放不受阻塞、
异步结果仅作用于所属会话、凭据和字幕内容不会泄漏到诊断信息、安装包行为符合已记录的
产品边界。

- 可自动化的行为变更 MUST 包含自动化回归覆盖。
- 当自动化无法证明跨运行时、打包、权限或播放器宿主行为时，MUST 保留明确的集成验证或
  人工验收任务。
- 未完成验证 MUST 继续作为可执行工作清晰可见，MUST NOT 根据推断标记完成，也不得被
  无关的通过测试替代。
- 只有所选轨道要求的检查全部通过，且当前产物与实现一致，变更才视为完成。

### II. 生产代码无注释且默认仅使用英语

生产代码变更 MUST NOT 添加行注释、块注释或文档注释。实现 MUST 通过清晰的命名、职责边界
和结构表达意图；无法直接读懂的实现 MUST 重构为更清晰的代码，MUST NOT 依赖新增注释解释。

生产代码中的自然语言内容 MUST 使用英语。除非功能明确需要支持非英语本地化，生产代码
MUST NOT 包含任何非英语自然语言内容。需要非英语本地化时，非英语内容 MUST 仅限该功能所需
的本地化资源或面向用户的数据；标识符、可执行逻辑和非本地化常量 MUST 使用英语。测试、
SDD 产物和项目文档不属于本原则所称的生产代码，并继续遵守各自的语言与质量规则。

## 治理

本宪法管理项目规划和实现实践。修订 MUST 记录理由、更新语义化版本，并审查受影响的有效
SDD 产物。

- MAJOR：以不兼容方式移除或重新定义核心原则。
- MINOR：新增原则或实质扩大强制性指导。
- PATCH：只澄清文字，不改变约束义务。
