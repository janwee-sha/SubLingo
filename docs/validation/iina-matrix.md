## Evidence from IINA 1.4.4

1. The official `iina-plugin link` command created the development link successfully.
2. IINA discovered the plugin after its required `subtitle` and `preferences` permissions were declared and the development plugin was enabled. The Plugins menu exposed both `SubLingo` and `SubLingo (Global)` developer contexts, and the player plugin panel displayed a SubLingo tab.
3. The first production bundle was rejected at runtime because Parcel had emitted CommonJS `require(...)` and `module.exports` references. The build now embeds dependencies and package verification rejects this regression.
4. An early embedded build entered a crash/reopen loop. The 2026-08-10 01:52:14 report recorded `EXC_BREAKPOINT / SIGTRAP` in `JavascriptAPIGlobalController.postMessage`; global→player replies now cross a zero-delay timer boundary.
5. A later reload exposed a second native trap at 02:50:46 in `JavascriptAPISidebarView.postMessage`: a 350 ms background timer posted after IINA had destroyed the sidebar. Main now updates an in-memory state snapshot, the live WebView polls for it, and the player timer is cleared on window close. `tests/contract/sidebar-lifecycle.test.ts` prevents the background-post regression.
6. The normal player now initializes its sidebar immediately instead of waiting for an unnecessary global player-ID round trip. Global callbacks still use IINA's real player identifier for replies and per-window provider leases.
7. The helper resolver found the executable through the real `SubLingo.iinaplugin-dev` symlink even though IINA reports the link itself as `isDir: false`. Discovery now prefers the canonical installed package and fails safely if multiple identifier-matching development packages are ambiguous.
8. In the actual IINA sidebar, OpenAI-compatible and Ollama were the only service choices. Switching changed endpoint defaults and hints, preserved a required Model ID field for both services, hid the API key for Ollama, and restored it for OpenAI-compatible. CSS cards, labels, and controls rendered aligned at the narrow sidebar width.
9. OpenAI-compatible treats the endpoint field literally as an API root. Entering `https://omni.janwee.blog/v1/chat/completions` remained unchanged in the Profile editor and previewed `.../chat/completions/chat/completions`, making the invalid double suffix visible instead of silently canonicalizing it. With no key persisted in the old build, Test reached the remote service and returned the expected authentication error rather than the earlier endpoint-rejected/helper error.
10. Each Profile row exposed Test, Select, Edit, and Delete. Edit loaded the same Profile ID and revision into an `Update profile` editor; `New profile` returned to create mode. The Reset Vault control was absent. Delete uses IINA's native confirmation and is covered by automated metadata, credential, cancellation, and multi-window invalidation tests; no real saved Profile was permanently deleted during manual validation.
11. Test, Select, translation enable/disable, save/update, language save, and delete operations expose request-correlated busy/success/error/cancelled feedback. Manual Test showed both success and authentication-error states, Select showed success, and the translation toggle announced enabled/disabled without session polling overwriting the operation state.
12. Before short provider wire IDs were introduced, `translategemma:12b` did not reliably reproduce source IDs such as `srt:0:0:1000`. The final adapters send `c1`, `c2`, and so on, validate that closed set, then restore exact source IDs before caching.
13. The then-current `0.1.0` build translated the six-cue `/Users/ianhsia/Movies/Test/demo.srt` through Ollama: Session reached Running, the cache reached 6/6, and the subtitle menu contained the generated `sublingo-player-….srt` second track.
14. IINA keeps the same main JavaScript context when the player closes back to the home window. The close handler now tears down only the video session and selection while retaining the scheduler. After closing and reopening the same video, selecting Ollama again produced a second independent Running session with cache 6/6 and a generated second track.
15. The formal 0.1.1 package installed as `SubLingo 0.1.1`; package/helper/main/global hashes matched the staged build, no development symlink existed, and the Uninstall button was enabled. Ollama Test launched `sublingo-transport` and IINA connected to its loopback port, but IINA serialized `data: {}` as a zero-byte body. The strict 0.1.1 `/v1/health` contract returned HTTP 400, which surfaced as helper unavailable. Version 0.1.2 accepts only zero-byte or literal `{}` health bodies and has native regressions for the accepted forms plus rejection of caller fields.
16. The formal 0.1.2 package and installed helper/main/global hashes matched exactly, with no development symlink. Ollama Test passed, proving the bodyless-health correction. Selecting Ollama started real subtitle work, but the final-position one-cue request returned the schema-valid `{"translations":[]}` and exhausted partial-result retries, leaving cache 0. Version 0.1.3 sets each split request's dynamic schema `minItems`/`maxItems` to its wire-ID count; the exact failing cue then returned a non-empty Chinese result, and the six-cue live adapter passed all IDs through three requests.
17. The formal 0.1.3 package installed as a normal directory with exact helper/main/global hashes. Ollama Test passed; actual playback translated the exact final single cue and then all six cues, with `demo.srt` selected as primary and generated track `#3` selected as secondary. A new OpenAI-compatible Profile saved its credential to the `0600` file under a `0700` directory, passed Test, translated all six cues, and selected a new generated secondary track. After quitting and reopening IINA, the Profile still displayed `key saved` with no Keychain/password prompt and Test passed while the helper was alive. Once the helper reached its 300-second idle exit, IINA rejected the stale loopback request without a helper response body; 0.1.3 mapped that to non-recoverable `HELPER_PROTOCOL`, so profile refresh showed `no key saved`, credential replacement failed, and Test misleadingly reported an endpoint rejection. Independent IINA `utils.exec`, ready-frame hook, credential read, system/direct helper requests, strict JSON Schema requests, and the remote adapter all passed, isolating the defect to the stale-session error mapping. Version 0.1.4 maps IINA's `helper-rpc-failed` to recoverable `HELPER_UNAVAILABLE`, allowing `TransportSupervisor` to start a replacement before reading credentials or sending a provider body.
18. The formal 0.1.4 package installed as a normal directory, reported version 0.1.4, matched the staged main/global/helper hashes, and exposed an enabled Uninstall button. OpenAI-compatible and Ollama Test both passed; each actual playback translated all six cues, reached cache 6/6, generated a new SubLingo SRT track, and displayed the original English subtitle with the translated Chinese second subtitle. Editing `Acceptance OpenAI` and updating with a blank key kept exactly one Profile row and retained `key saved`; Delete opened IINA's permanent-removal confirmation, and cancelling produced `Operation cancelled. Nothing was changed.` After helper PID 79808 naturally exited following at least 300 seconds without an RPC, OpenAI-compatible Test passed without restarting IINA, retained the credential, and started replacement helper PID 79930. This closes the installed stale-session recovery defect without introducing macOS Keychain.
